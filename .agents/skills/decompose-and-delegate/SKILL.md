# Decompose and Delegate

## 目的

メインセッションのコンテキスト消費を抑えつつ、サブエージェントの能力の制約による作業品質の低下を防ぐ。

## 原則

- メインエージェントは全体の理解、方針決定、タスク分解、成果の統合および最終判断を担う。
- 調査、分析、実装、検証などの個別作業は、可能な限りサブエージェントに委任する。
- サブエージェントが広範なコンテキストや高度な推論を必要とせずに遂行できる作業単位を設計する。
- 機械的な分割ではなく、意味的な境界を優先する。

### 委任と直接処理の判断基準

分割・委任のコストが作業自体のコストを上回る場合は、メインエージェントが直接処理する。

- **直接処理する目安:** 単一ファイルの軽微な修正、1〜2回のツール呼び出しで完結する確認作業。
- **委任する目安:** 複数ファイルにまたがる調査、独立して並列実行できる実装・テスト、大量のログやコードを読む必要がある作業。

## 実行手順

以下の手順に従ってタスクを分解・委任・統合する。

### 1. タスク分解

タスクの性質に応じて、適切な分割軸を選択する（複数組み合わせ可）。ただし、分割そのものを目的とせず、作業品質と委任効率を優先する。

- **分割軸:** 機能 / ドメイン / レイヤー / モジュール / 責務 / 調査対象 / 検証観点

各作業単位は以下の条件を満たすように設計する。

- 目的と責任範囲が明確である。
- 必要な前提情報が限定されている。
- 他の作業単位への依存が最小限である。
- サブエージェントの能力で遂行可能である。
- 成果物と完了条件が明確である。
- 成果を独立して検証できる。

### 2. 委任

各サブエージェントへの指示には、以下の情報を過不足なく提供する。作業に不要なコンテキストは渡さないが、必要な前提情報まで省略してはならない。

- 作業目的
- 対象範囲
- 必要な前提情報
- 制約事項
- 期待する成果物
- 完了条件

独立した作業は並列に委任し、依存関係のある作業はその依存順序に従って委任する。

### 3. 成果の回収

サブエージェントへの委任プロンプトには、**作業過程の逐次報告やコード全文の貼り付けを禁止**し、以下の見出しのみで簡潔に（箇条書き推奨）返却するよう出力形式を指定する。

- **作業結果:** 実施内容と結論の要約
- **判断根拠・参照箇所:** 根拠となるファイルパス、行番号、コマンド結果など
- **発見した問題:** 作業中に見つかったバグ、懸念点、設計上の課題
- **未解決事項:** 権限不足や情報不足で完了できなかった項目
- **検証結果:** 実行したテストや確認の成否

詳細なログや長大な中間成果物が必要な場合は、一時ファイル（または指定パス）に書き出させ、メインセッションには**要約とファイルパスのみ**を返却させる。

### 4. 統合と検証

メインエージェントは回収した成果を無条件に信用せず、以下の観点で評価する。

- 当初の目的との整合性
- 作業範囲の網羅性
- 成果間の矛盾や重複
- 責務境界をまたぐ影響
- 判断根拠の妥当性
- 未解決事項の有無

不足や不整合がある場合は、対象範囲をさらに限定して再委任するか、必要な箇所を直接検証する。最終的な判断と成果の品質に対する責任は、メインエージェントが負う。
